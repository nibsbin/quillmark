# 0.104 → 0.105 — card scalars are value-objects

A **card's** declared `string` / `integer` / `number` fields reach a Typst plate
as a two-projection value-object, the shape `date` / `datetime` fields have used
since 0.94:

```typst
(card.from.display)()   // content: rendered ink, click-to-edit, per card
card.from.value         // the raw str/int: packages, string ops, comparisons
```

Root fields (`data.subject`), array elements (`card.signature_block`),
booleans, `none`, and undeclared keys are **unchanged**. So is `$kind`: it is
not a schema property, so `card.at("$kind") == "indorsement"` dispatch needs no
edit.

## Why

A region needs to name *which* card it belongs to. A plate reads every card
through one shared loop variable — `card.<field>`, one expression site for N
cards — so the backend's plate scan cannot tell instance 0's cell from
instance 2's. Rendering through a closure the backend generates **per cell**
does: the closure's ink is born at its own definition site, so each card's value
carries its own address. Before this, the only way to get a click target on a
card scalar was to bind a `form-field` to it, which stamps a real AcroForm
widget into the PDF just to buy a rectangle.

## Migrating a plate

| 0.104 | 0.105 |
|---|---|
| `#card.from` | `#(card.from.display)()` |
| `pkg-fn(from: card.from)` | `pkg-fn(from: (card.from.display)())` if it *places* the value; `card.from.value` if it does string work |
| `upper(card.from)`, `card.from.trim()` | `upper(card.from.value)`, `card.from.value.trim()` |
| `if card.title != ""` | `if card.title.value != ""` |
| `form-field("Qty", value: card.qty)` | `form-field("Qty", value: card.qty.value)` |
| `card.at("format", default: "standard")` | `let f = card.at("format", default: none)` then `if f == none { "standard" } else { f.value }` |

Prefer `(…display)()` wherever the value is *placed*: that is what buys the
region. Reach for `.value` when something consumes it as a native value — an
`assert(x in (..))`, a `.starts-with(..)`, a `+` concatenation, a widget's
`value:`.

`display` takes no arguments here (`(card.from.display)()`), where a date's
takes the format pattern. The parentheses around `card.from.display` are
required for the same reason they are on dates: Typst reserves dict-key method
sugar for built-in dict methods, so a stored closure is called through the
parenthesized form.

### The one break a Typst error will not catch

Every other break above fails the compile — a dictionary where a package wanted
a string is a hard error. A **comparison against the bare cell** does not:

```typst
#if card.title != "" { section-header(card.title) }   // now ALWAYS true
```

A dictionary is never equal to a string, so the guard stops guarding and the
branch renders for a blank field too. Audit `== ""` / `!= ""` against card
fields and route them through `.value`. (A blank field still lowers to a
value-object rather than degrading to `none`, which is what keeps `.value`
total — no presence guard needed — and is the trade that leaves this comparison
silent.)

Blank cells draw no ink and so surface **no region**, exactly as a blank
content field does.

## What this does not cover

`card.signature_block` and other array fields keep their raw element values.
`$cards.<kind>.<n>.<field>.<i>` is a real schema address, but a plate reaches an
element through a *second* shared site (an index or `.map`), so per-element
identity is its own problem; bind a widget for those as before.

## Nothing else moves

Documents, stored blobs, the plate-JSON wire shape, and every non-Typst surface
are untouched — the change is entirely in what the Typst helper package
generates. Region *consumers* need no change either: card scalar regions arrive
on `session.regions()` / `fieldAt` keyed on the same `$cards.<kind>.<n>.<field>`
addresses everything else already uses, where before they simply were not there.
