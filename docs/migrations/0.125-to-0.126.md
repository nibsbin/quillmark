# 0.125 → 0.126 — a quill's font collections load, `status_report` stores enum ids, a `$quill` name may carry a collection, an acroform quill's field spec is `form.yaml`, a Typst quill's plate is `plate.typ` by name and its `typst:` section is strict, a card groups fields under a top-level `object` where it declared `sections:`, a quill's `version` is `MAJOR.MINOR.PATCH` and a `$quill` selector `@MAJOR.MINOR` or exact, a text field is `text` or `richtext`, one line unless it declares `multiline: true`, and script links, runaway YAML expansion and bodies nested past 12 levels are refused

The first break nothing reports: **a Typst quill holding `plate.typ` at its
root and declaring no `typst.plate_file` renders that plate, where it rendered
a blank page.** The backend finds the plate by name, so a `plate.typ` the quill
carried without wiring it up now compiles. Every render of such a quill
changes, and no diagnostic says so. A `plate.typ` there that does not compile,
a stale draft or one importing a file the quill no longer holds, fails `open`
and `quillmark validate`. Delete or fix it, or declare the plate the quill
means as `typst.plate_file`.

The second break nothing reports: **a `.ttc` or `.otc` under `assets/fonts/` or
inside a vendored package loads every face it holds, where the backend skipped
it.** A plate naming a collection's family renders in it, where it rendered in
a fallback face and warned `unknown font family`. A quill whose only fonts are
collections renders in them, where it rendered in the embedded Roboto, so a
plate there naming `Roboto` warns `unknown font family`.

The third break: **the `status_report` fixture quill's `state` stores
`on_track`, `at_risk` and `blocked`, where it stored `on track`, `at risk` and
`blocked`.** The quill keeps `version: 0.1.0`. A document holding `state: at
risk` fails `validation::enum_violation` and does not render. Rewrite `on track`
to `on_track` and `at risk` to `at_risk`; the banner prints the same text.

**A text field is `text` or `richtext`, and either is one line unless it
declares `multiline: true`.** `type: plaintext` is `type: text`, `type: string`
is retired in favor of `text`, and `inline:` and `ui.multiline` give way to the
one key `multiline:`. Each retired spelling fails the load as
`quill::field_parse_error`, its message naming the replacement, and a `richtext`
must spell `multiline:` either way for this release, so none of this migrates
silently. Rewrite each declaration:

| Was | Now |
|---|---|
| `type: plaintext` with `inline: true` | `type: text` |
| `type: plaintext` | `type: text` with `multiline: true` |
| `type: string` | `type: text`, plus `multiline: true` where a value takes more than one line |
| `type: richtext` with `inline: true` | `type: richtext` with `multiline: false` |
| `type: richtext` | `type: richtext` with `multiline: true` |
| `ui: { multiline: true }` | `multiline: true` on a `text` or `richtext`; delete it elsewhere |
| `string?`, `items: { type: string }` | `text?`, `items: { type: text }` |

No stored document changes: `string`, `plaintext` and `text` all rest as the
verbatim string.

**A former `string` value reaches a Typst plate as content, where it was a
`str`**, so it prints with nav and click-to-edit. A plate that computes with it
— `upper`, `split`, `len`, a comparison, `set document(author: ..)`, a package
that does any of these — fails to compile until it reads the value through the
new `qm.str(..)`, which returns the verbatim string (`qm.data.memo_for.map(qm.str)`
for an array). Printing it, `#qm.data.title`, needs no change. A matrix added
item's `title` is a one-line `text` cell, content in the plate.

Two changes nothing reports:

- **`schema()` emits `quillmark:multiline: true` on a field that admits more
  than one line, and no `quillmark:inline`.** The polarity inverts: a consumer
  that read the absence of `quillmark:inline` as "block" now reads every
  one-line field as a block. Branch on `quillmark:multiline` instead. A former
  `string` field is `{type: object, contentMediaType:
  application/quillmark-content+json, quillmark:plain: true}`, where it was
  `{type: string}`, and the blueprint prints `text<plain>`,
  `text(multiline)<plain>` and `richtext(multiline)<markdown>` where it printed
  `string`, `plaintext<plain>` and `richtext<markdown>`. WASM `QuillFieldUi` has
  no `multiline`; read the field's own.
- **An acroform text widget is multiline exactly where its field declares
  `multiline: true`**, where it read `ui.multiline`. A block `richtext` without
  that hint bound a one-line widget, which a value holding a newline widened at
  render (#2217); it now binds multiline.

`validation::not_inline` is `validation::not_single_line` and
`edit::field_not_inline` is `edit::field_not_single_line`, and their `codec`
argument names `text` where it named `plaintext`.

A link whose target's scheme is `javascript:`, `vbscript:`, `data:` or `file:`
renders as its text alone under Typst, where it rendered a live link in PDF and
SVG. A card-yaml block whose expanded aliases and tags pass twice the block's
bytes plus 4 KiB of scalars, or the block's bytes plus 4 KiB of nodes, fails its
YAML parse, where it parsed.

**A body nests at most 12 levels deep, where it nested 100.** The list items,
quotes and elements open at one point of a body, and the marks open there,
count toward the bound (markdown spec §8). A body past it fails
`parse::body_import` at the body's `path`, `main.body` or
`cards.<kind>[i].body`, where it imported and failed to render once Typst's
show-rule depth ran out, by 16 quotes or 32 lists. Flatten the deepest levels.
A stored row holding such a body fails to load, uncoded, its message naming
`NestingTooDeep`: open it with a 0.125 build and flatten it before upgrading.
`MAX_NESTING_DEPTH` is `12`, and `ParseError::BodyImport` holds
`{ path, message }`.

**A quill declaring a field named `body`, on `main` or a card kind, fails to
load with `quill::reserved_field_name`**, where it loaded and
the field shared its path, `main.body` or `cards.<kind>[i].body`, with the
card's body. Rename the field, and its key in every document.

**An acroform quill's field spec is `form.yaml`, where it was `form.json`.**
A quill holding `form.json`, alone or beside `form.yaml`, fails to open as
`acroform::legacy_form_json`. Rename the file: JSON is YAML 1.2, so its
contents load unchanged, and the `schema` tag stays `quillmark/form@0.2.0`. A
generator may keep writing JSON, under the new name. Three contents fail as
`acroform::invalid_form_spec` where `form.json` loaded:

- A string holding DEL, a C1 control other than U+0085, U+FFFE or U+FFFF
  written raw, which the parser refuses. Escape it, as `\u007f`.
- A key written twice in one object, which `form.json` read as its last value
  when the key was one the spec does not know. Delete the duplicate.
- A `rect` value past `f32` range, such as `1e39`, which `form.json` read as
  infinity.

Any spec that fails to parse is `acroform::invalid_form_spec`, where it was
`acroform::invalid_form_json`, now located at its line and column in
`form.yaml`. A quill with no spec is `acroform::missing_form_spec`, where it
was `acroform::missing_form_json`.

**A Typst quill's plate is `plate.typ` at the quill root, found by name, and
the `typst:` section holds only `plate_file`, which names another path.** Two
kinds of quill that rendered now fail, and no type checker sees either:

- **A quill holding no `plate.typ` and declaring no `typst.plate_file` fails
  to open as `typst::plate_missing`**, its hint naming both, where it rendered
  a blank page and reported nothing. `quillmark validate` reports it, under
  `--no-render` too. A `plate_file` that is not a string, such as `5` or an
  empty `plate_file:`, or that names no path, such as `""` or `./`, fails as
  `typst::plate_path_invalid`, where it rendered the same blank page or failed
  as `typst::plate_missing`. Ship the plate as `plate.typ`, or name it.
- **A key under `typst:` other than `plate_file` fails the load as
  `quill::unknown_backend_key`**, carrying `backend` and `key` in `args` and a
  hint listing the valid keys, where the quill loaded and every render and
  session warned `typst::unknown_key`, which is retired. `typst.packages` is
  the common one: delete it, since a quill vendors its packages under
  `packages/`. An `acroform:` section holding any key fails the same way, since
  that backend reads none.

A backend section that is a scalar or a sequence fails as
`quill::invalid_backend_section`, where it was ignored; an empty one, `typst:`
alone, reads as no keys. A quill whose
`typst: { plate_file: plate.typ }` names the default loads unchanged, and may
drop the section. `quillmark_typst::plate_file`, re-exported as
`quillmark::typst_plate_file`, returns `Result<String, RenderError>`, where its
`Ok` held an `Option<String>`.

Under WASM, **a render that traps rejects as `runtime::backend_trapped`**, the
`WebAssembly.RuntimeError` on its `cause`, where it rejected as an uncoded
`attempted to take ownership of Rust value while it was borrowed`. A host
matching that message routes on the code, and discards the realm.

**A card declaring `sections:` fails to load with `quill::invalid_card_schema`**,
its hint naming the top-level `object`. A card groups fields by declaring a
top-level `object` keyed by the group's id, with the group's `title` and its
fields as `properties`
([Grouping](../quills/quill-yaml-reference.md#grouping)). The object is data:
documents nest each group's keys under its id, and a plate reads
`data.<group>.<field>`. To keep every address, move each section's fields up
under the card's `fields:` instead, ungrouped. `ui.group` / `ui.groups` load as
before, with `quill::deprecated_groups` hinting the `object` rewrite.
`quill::empty_section`, `quill::invalid_section_id`,
`quill::mixed_sectioning` and `quill::duplicate_field`, which named a field
declared twice across `fields:` and the sections, are retired with the key. The
`usaf_memo` fixture declares its fields ungrouped, so its schema emits no
`ui.groups` or `ui.group`; its addresses are unchanged.

**A `$quill` name may carry a collection, `borb.usaf_memo@1.2`, and no longer
starts with `_`.** A quill name and a collection name are each
`[a-z][a-z0-9_]*`, at most 64 characters; `quill.name` in `Quill.yaml` holds to
the same cap. The engine pairs a document with a quill by the part after the
`.`. `QuillReference` carries `collection: Option<String>`.

**A blueprint's `$kind: main` line carries `main.title` and
`main.description`, and nothing where neither is declared**, where it fell back
to `quill.description`. `quill.description` describes the package, for a gallery
or a quill picker, and never reaches the blueprint. A quill that wants the line
kept copies its `quill.description` to `main.description`. Documents are
unaffected.

**A `$quill` selector is `@MAJOR.MINOR` or `@MAJOR.MINOR.PATCH`, so
`$quill: memo@1` fails `parse::invalid_quill_reference`**, where it matched any
`1.x.x`. A quill's version ranks a bump by what it costs a stored document, and
a MINOR bump needs each one rewritten, so a lone major names no compatible
series ([Quill Versioning](../quills/versioning.md)). Rewrite the reference to
the series the document was written against, `memo@1.2`, or drop the selector
to match any version. `VersionSelector::Major` is removed.

**A stored row whose `$quill` is a lone major fails to load, and 0.126 cannot
open it to fix it.** No storage door reports `parse::invalid_quill_reference`.
WASM `fromStored` / `loadStored` and Python `Document.from_stored` throw one
uncoded diagnostic whose message holds `invalid quill reference "memo@1"`. In
Rust, `Document::try_from(StoredDocument)` returns
`StorageError::InvalidQuillReference { value, reason }`, and
`serde_json::from_str::<Document>` a `serde_json::Error` carrying the same
message. Rewrite such rows before upgrading. A row is JSON, so a text match
finds it:

```sh
grep -lE '"type":[[:space:]]*"quill",[[:space:]]*"value":[[:space:]]*"[a-z_][a-z0-9_]*@[0-9]+"' <rows>
```

With a 0.125 build, open each row, set the series and save it: `fromStored`,
`setQuillRef("memo@1.2")`, `toStored` (Python `from_stored`, `set_quill_ref`,
`to_stored`). Without one, rewrite the string in place; nothing else in the row
changes:

```sh
sed -i -E 's/("type":[[:space:]]*"quill",[[:space:]]*"value":[[:space:]]*"memo@1)"/\1.2"/' <row>
```

**A document the quill creates pins its `MAJOR.MINOR`, `name@1.2`, where it
pinned the exact version, `name@1.2.0`.** The seeded, empty and example
documents carry it (`seed_document`, `empty_document`, `example_document`, WASM
`seedDocument`, `emptyDocument`, `exampleDocument`), and so does the
blueprint's `$quill` line. Every patch in the series reads such a document,
where a patch release failed it with `quill::version_mismatch`. A host
comparing a created document's `quillRef` / `quill_ref` to `name@version`
compares to `name@MAJOR.MINOR`; Python's `Quill.quill_ref` stays
`name@MAJOR.MINOR.PATCH`, so it no longer equals one. A document an earlier
build created keeps its exact pin: rewrite it to `name@MAJOR.MINOR` for a later
patch to read it.

**A quill's `version` is `MAJOR.MINOR.PATCH`, so `version: "1.2"` fails to load
with `quill::invalid_version`**, where it loaded. Write `1.2.0`. An unquoted
`version: 1.10`, which read as `1.10`, fails the same way: write `1.10.0`.
