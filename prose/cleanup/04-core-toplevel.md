# Cleanup review: core (top-level modules)

Scope: `crates/core/src/{lib,value,region,writer,reader,error,session,version,path,backend,normalize,quill,types}.rs` (4483 LOC) + `crates/core/tests/{spec_conformance_probe,markdown_field_test}.rs` (317 LOC) + `crates/core/examples/print_blueprint.rs` (30 LOC). `document/` and `quill/` (the directories, not `quill.rs`) excluded per assignment; read for caller verification only.

Read `prose/canon/ARCHITECTURE.md`, `ERROR.md`, `VERSIONING.md` first. This module set is unusually dense and deliberate — most public surface traces to a real caller in `crates/bindings/{python,wasm}` or `crates/backends/*`. Findings below are the exceptions.

## Findings

### F1: `QuillValue`'s delegating accessors duplicate its own `Deref` impl
- **Category**: duplicate-helper
- **Location**: `crates/core/src/value.rs:394-433` (the `is_null`/`as_str`/`as_bool`/`as_i64`/`as_u64`/`as_f64`/`as_array`/`as_object` block), vs. the `Deref<Target = serde_json::Value>` impl at `value.rs:340-346`
- **Evidence**: `QuillValue` derefs to `&serde_json::Value` (`fn deref(&self) -> &Self::Target { self.as_json() }`). `serde_json::Value` already defines `is_null`, `as_str`, `as_bool`, `as_i64`, `as_u64`, `as_f64`, `as_array() -> Option<&Vec<Value>>`, `as_object() -> Option<&Map<String, Value>>` with identical signatures. Every one of these eight inherent methods on `QuillValue` is byte-for-byte what Rust's method resolution would find via deref coercion if the inherent method didn't exist — `qv.as_str()` already compiles and returns the same value today whether or not the inherent method exists, because it forwards to `self.as_json().as_str()`, exactly what deref-then-call produces. This is the exact pattern the task brief called out as a prime suspect (`value.rs` conversions vs. `serde_json`/`serde_yaml`). The one method in that `impl` block that is *not* redundant, `get(&self, key: &str) -> Option<QuillValue>` (`value.rs:436-441`), stays — it returns `QuillValue` (preserving fill markers), not `&serde_json::Value`, so it isn't reachable through `Deref`.
- **Recommendation**: Delete the eight redundant methods (`is_null`, `as_str`, `as_bool`, `as_i64`, `as_u64`, `as_f64`, `as_array`, `as_object`) at `value.rs:394-433`, keeping `get`. Every existing call site (306+ occurrences of `.as_str()` alone across the workspace, similarly for the others) continues to compile unchanged via `Deref`.
- **Est. LOC removable**: ~42
- **Confidence**: high
- **Risk if removed**: none functionally — behavior is identical pre/post removal since `Deref` supplies the same method with the same signature. The only externally-visible change is that `cargo doc` stops listing these as inherent methods on `QuillValue` (they'd still show under "Methods from Deref<Target = Value>"). `QuillValue` is published API, but this is a pure non-breaking cleanup, not a behavior or signature change.

### F2: `TypedWriter::remove_card` is unreachable-in-practice forwarding
- **Category**: dead-code / symmetric-api-bloat
- **Location**: `crates/core/src/writer.rs:143-148`
- **Evidence**: The method's entire body is `self.doc.remove_card(index)`. Grepped every `.remove_card(` call site in the workspace: WASM's `Document::removeCard` (`crates/bindings/wasm/src/engine.rs:1694-1695`) calls `self.inner.remove_card(index)` — `self.inner` is the core `Document`, not a `TypedWriter`. Python's `PyWriter::remove_card` (`crates/bindings/python/src/types.rs:787`) calls `doc.inner.remove_card(index)` directly, bypassing `quill.inner.writer(...)` even though every other `PyWriter` method goes through the writer. The only call to `TypedWriter::remove_card` in the whole workspace is its own unit test (`writer.rs:388-423`, `add_card_at_inserts_and_remove_card_returns`). The doc comment claims it "mirror[s] the JS `writer.removeCard` sugar" — but `removeCard` lives on WASM's `Document`, not on a `Writer` type; no such method exists on the WASM writer surface. The doc comment is stale/inaccurate as well as the method being unused.
- **Recommendation**: Delete `TypedWriter::remove_card` (`writer.rs:143-148`) and its doc comment; drop the `remove_card` assertions from the `add_card_at_inserts_and_remove_card_returns` test (or point them at `Document::remove_card` directly, which is what both bindings actually call). No consumer needs to change.
- **Est. LOC removable**: ~8 (method + doc comment; test simplification not counted)
- **Confidence**: high
- **Risk if removed**: none found — zero real callers, and removal doesn't touch `Document::remove_card` (the document/ subdirectory owns that, out of this review's scope, and it stays).

### F3: `ReadValue::as_text` / `ReadValue::as_value` have no callers
- **Category**: dead-code
- **Location**: `crates/core/src/reader.rs:74-91`
- **Evidence**: Neither method is called anywhere in the workspace, including `reader.rs`'s own test module. Both bindings that consume `ReadValue` pattern-match its variants directly instead: `crates/bindings/python/src/types.rs:1227-1229` (`Some(ReadValue::Markdown(s)) | Some(ReadValue::Plaintext(s)) => ...`, `Some(ReadValue::Value(v)) => ...`) and `crates/bindings/wasm/src/engine.rs:1046-1048` do the identical match, ignoring `as_text`/`as_value` entirely. The accessors were added "for symmetry" with a typical projection-enum API but the two real consumers both needed to distinguish `Markdown` from `Plaintext` (not just "is it text"), so they matched instead of calling the flattening accessor.
- **Recommendation**: Delete both methods (`reader.rs:74-91`, ~15 lines including doc comments). If a future consumer wants "any text, regardless of markdown/plaintext," reintroduce then.
- **Est. LOC removable**: ~15
- **Confidence**: high
- **Risk if removed**: low. `ReadValue` and its variants stay public (they're the return type of `TypedReader::get`, heavily used); only these two unused accessor methods go. `quillmark-core` is published, so this is a technically-breaking API removal for any hypothetical external consumer — flagging per the published-crate caveat — but nothing in-workspace, including both first-party bindings, uses them.

### F4: `Version`'s `PartialOrd`/`Ord` impl has no caller
- **Category**: dead-code
- **Location**: `crates/core/src/version.rs:74-90`
- **Evidence**: `Version` comparison in the actual version-matching path (`VersionSelector::matches`, `version.rs:110-117`) uses only field equality (`*want == v`, `v.major == *major`, etc.), never ordering. Grepped for `.cmp(`, `.max(`, `.min(`, `.sort` against `Version` instances workspace-wide: the only hits are the `Ord`/`PartialOrd` impl's own body and `test_version_ordering` (`version.rs:306-318`). `crates/fixtures/src/lib.rs:32` sorts versioned quill directories but does so with its own ad hoc `Vec<u64>` parse-and-compare, not `quillmark_core::Version` — a second, independent implementation of "compare version-like strings" that doesn't reuse this `Ord` impl (noted for awareness, not itself a removal candidate — different input type, out of this review's file scope).
- **Recommendation**: Lower confidence than F1-F3 — `Version` is exported from a published crate (`ARCHITECTURE.md` lists it explicitly) and `Ord` is a plausible, cheap thing to keep on a semver-shaped type for external consumers even absent an in-workspace caller. Flagging for awareness rather than recommending outright deletion; if the maintainers want to trim it, `PartialOrd`/`Ord` (16 lines) plus `test_version_ordering` (13 lines) go together.
- **Est. LOC removable**: ~29 (optional)
- **Confidence**: low
- **Risk if removed**: `Version` is public API on a published crate; removing `Ord`/`PartialOrd` is a breaking change for any external consumer sorting/comparing `Version`s directly (as opposed to matching a `VersionSelector`). Not recommended without checking downstream usage outside this workspace.

### F5: `Version::new` / `QuillReference::new` have no in-workspace caller outside their own tests
- **Category**: dead-code
- **Location**: `crates/core/src/version.rs:22-28` (`Version::new`), `version.rs:200-202` (`QuillReference::new`)
- **Evidence**: `Version::new` is called only from `version.rs`'s own test module (10 call sites, all in `#[cfg(test)]`). `QuillReference::new` is likewise called only from its own tests (`version.rs:428-440`); production code uses `QuillReference::latest` (`crates/core/src/quill/seed.rs:101`) or `FromStr` (parsing `$quill:` lines) exclusively.
- **Recommendation**: No action recommended — these are the obvious, idiomatic constructors for two published, exported types (`Version`, `QuillReference`), and a struct-literal-shaped constructor with no in-workspace caller is normal for a library's public API (construct-in-code is an alternative to parse-from-string for an embedding application). Listed for completeness per the audit brief, not as an actionable removal.
- **Est. LOC removable**: 0 (not recommended)
- **Confidence**: low
- **Risk if removed**: breaking change to published API for plausible legitimate use; no evidence of actual dead-ness beyond "no workspace caller."

## Load-bearing (looks redundant, is not)

- **`backend::formats_support_canvas` vs. `LiveSession::supports_canvas`** (`backend.rs:45-49`, `session.rs:199-201`) — two "can this backend paint a canvas" predicates that look like the same fact computed twice. They're deliberately not unified: `formats_support_canvas` is a pre-session hint keyed on `OutputFormat` (usable before paying to `open()` a session), `supports_canvas` is the authoritative, session-derived answer keyed on the actual `page_size_pt` seam. Both are documented as such and both have real callers (`crates/quillmark/src/orchestration/engine.rs:120` for the hint; typst/pdfform backends' sessions for the authoritative one).
- **`plate_addr_to_doc_path` / `doc_path_to_plate_addr`** (`region.rs:229-283`) — two ~25-line functions that look like they could be one bidirectional mapping. They're true inverses over related but distinct grammars (plate-space `$cards.<kind>.<ordinal>.<field>` vs. document-model `DocPath`), each with its own edge cases (`$`-prefix detection one way, kind-at-index validation the other), and both directions have real callers (WASM `_readerGet`/`fieldAt`/`positionAt`/`locate` in one direction, `formatDocPath`-adjacent geometry queries in the other). Collapsing them would not reduce logic, only obscure the two directions' different failure modes.
- **`DocPath`'s `Display`/`FromStr` pair** (`path.rs:158-249`) — a serializer and parser that look like they could share more code (both branch on `main`/`cards` heads). They already share the maximum reasonable amount: `FromStr` reuses a common `scan` tokenizer and reclassifies; the two "halves" differ because encoding is structural (walk `DocSeg`) and decoding is grammatical (recognize head shapes), which are genuinely different problems. Not a duplication target.
- **`QuillValue::json_depth_exceeds` vs. Python's `py_to_json_at` depth guard** — the module doc for `json_depth_exceeds` (`value.rs:143-166`) explicitly notes the Python binding's `py_to_json_at` (`crates/bindings/python/src/types.rs:1400+`) reimplements the same container-level counting rule independently rather than calling into this function. This looks like exactly the kind of duplicate-logic this review should flag, but it's structurally forced: `py_to_json_at` walks `PyAny` (a Python object graph) during conversion to `serde_json::Value`, fail-fast, before a `serde_json::Value` exists to hand to `json_depth_exceeds`. The two can't share code without either converting-then-checking (defeats the fail-fast purpose) or introducing a generic-over-input-type walker (real complexity for one call site). Out of this review's file scope regardless (Python binding), noted for awareness only.

## Summary of untouched-but-verified-live surface

`writer.rs` and `reader.rs` (the `TypedWriter`/`TypedReader`/`CardWriter`/`CardReader` "symmetric API bloat" candidate the brief flagged for scrutiny) checked out clean except for F2/F3 above: every other method (`set`, `set_all`, `set_body`, `revise_field`, `add_card`, `card`, `get`, `get_body`, `kind`) has a real, verified call site in at least one of the Python or WASM bindings. `error.rs`'s `ParseError` variants are all constructed at real parse sites in `document/`; `RenderError::new` vs. `from_diag` are both genuinely used (multi- vs. single-diagnostic construction). `session.rs`, `region.rs`, `types.rs`, `backend.rs`, `normalize.rs`, `quill.rs` had no redundant-logic or dead-code findings — their public surface is fully accounted for by real callers in `crates/backends/{typst,pdfform}` and `crates/bindings/{python,wasm}`. `crates/core/tests/{spec_conformance_probe,markdown_field_test}.rs` have no low-value or near-duplicate tests — each test targets a distinct, named spec requirement or regression, none is a bare "doesn't panic" check, and message-string assertions are substring checks on stable prose rather than brittle full-string pins.
