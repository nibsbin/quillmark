# Cleanup review: quillmark orchestration + fuzz + fixtures

Scope: `crates/quillmark/src/` (314 LOC: `lib.rs` 32, `load.rs` 141, `orchestration/engine.rs` 129, `orchestration/mod.rs` 12) and its 15 integration tests (1510 LOC, `crates/quillmark/tests/*.rs`); `crates/fuzz/src/` (911 LOC across `coerce_fuzz.rs` 336, `convert_fuzz.rs` 333, `emit_roundtrip_fuzz.rs` 140, `parse_fuzz.rs` 86, `lib.rs` 16); `crates/fixtures/src/lib.rs` (62 LOC) and the 7 fixture Quills under `resources/quills/` (classic_resume, cmu_letter, richtext_form, sample_form, table_demo, taro, usaf_memo) plus 4 loose resource files. Cross-checked against `crates/core/src/quill/{compose,resolved,validation}.rs` tests, `crates/core/src/document/{prescan,yaml_hints}.rs` tests, and `crates/backends/typst/tests/content_regions.rs` / `sig_field.rs` / `emit.rs` unit tests.

## Findings

### F1: `multibyte_regression_test.rs` tests core's `Document::parse`, not quillmark, and two of five duplicate an existing core unit test verbatim
- **Category**: wrong-altitude-test
- **Location**: `crates/quillmark/tests/multibyte_regression_test.rs:23-43` (`em_and_en_dashes_in_block_scalar_bullets_parse_without_panic`), `:46-59` (`multibyte_after_dash_marker_does_not_panic`)
- **Evidence**: `quillmark::Document` is `pub use quillmark_core::Document` (`crates/quillmark/src/lib.rs:22-26`); this whole file calls only `Document::parse`, never touching `quillmark`'s own `load.rs` or `orchestration/engine.rs`. `crates/core/src/document/prescan.rs:978-999` (`sequence_with_multibyte_after_dash_does_not_panic`) already covers the identical regression class — en-dash, em-dash, smart-quote, emoji immediately after a `-` marker, plus the exact `bullets: |` block-scalar-with-mixed-dashes shape that motivated this file — by calling `prescan_fence_content` directly (no full `Document::parse`, no card-yaml wrapper, no quillmark facade). The two flagged tests are a strict subset of that core test's input list. The other three tests in the file (`multibyte_in_quoted_scalar_parses`, `multibyte_keys_do_not_panic_on_duplicate`, `multibyte_in_value_with_yaml_error_does_not_panic`) exercise a different scanner path (quoted-scalar parsing, YAML-error caret positioning) that is only generically covered by `crates/core/src/document/yaml_hints.rs:429-435` (`does_not_panic_on_multibyte_content`, em-dash + curly quotes) — not exact-input duplicates, so lower confidence on those three.
- **Recommendation**: Delete the two duplicate test functions. For the remaining three, they belong in `crates/core/src/document/tests/` (or as additions to `prescan.rs`'s own test module) since none of them need the quillmark crate at all — fold them into core's existing multibyte-panic coverage rather than keeping a facade-only file whose only job is to re-call a re-exported function.
- **Est. LOC removable**: ~35 directly (two functions); ~95 if the whole file relocates into core, netting to near-zero new LOC there since the panic-guard pattern already exists
- **Confidence**: high (the two flagged functions); medium (relocating the rest)
- **Coverage risk**: none for the two duplicates. For the other three, no regression coverage is lost by moving them (same assertions, just run against core directly) — only by deleting them outright, which is not recommended.

### F2: `default_values_test.rs`'s default/zero-fill assertions duplicate `core::quill::resolved.rs`'s ladder tests; the nested-null case does not
- **Category**: wrong-altitude-test
- **Location**: `crates/quillmark/tests/default_values_test.rs:73-132` (`test_defaults_applied_when_absent`), `:134-184` (`test_absent_must_fill_is_zero_filled`)
- **Evidence**: Both tests build a filesystem quill via `quill_from_path` purely to call `Quill::compile_data`, asserting: authored value wins, absent-with-default falls back to the default, absent-without-default zero-fills to `""`. `crates/core/src/quill/resolved.rs:281-297` (`scalar_sources_authored_default_zero`) proves the identical authored/default/zero ladder (`resolve_value_sourced`, the function `compile_data` itself calls — see `crates/core/src/quill/compose.rs:459-489`) via an in-memory `Quill::from_tree`, no disk I/O. `resolved.rs:333-371` (`every_row_is_byte_for_byte_with_compile_data`) additionally proves `resolve()`'s output is byte-identical to `compile_data()`'s for every field, so any drift in the zero-fill/default mechanism that these two quillmark tests would catch is already caught one layer down, faster. `test_nested_null_zero_fills_in_plate` (`default_values_test.rs:19-71`) is *not* duplicated — no core test covers a null nested inside both an object property and an array element reaching the plate — so it should stay.
- **Recommendation**: Delete `test_defaults_applied_when_absent` and `test_absent_must_fill_is_zero_filled`; keep `test_nested_null_zero_fills_in_plate` (rename the file to reflect its narrower remaining scope, e.g. `nested_null_zero_fill_test.rs`, if desired — not required).
- **Est. LOC removable**: ~110 (no Typst rendering involved, so no render-time savings — this is pure maintenance-debt reduction)
- **Confidence**: medium-high (the string/status-default and zero-fill mechanism is proven at core; the specific *numeric*-default case in `test_defaults_applied_when_absent` — `version: 1.0` → `Some(1.0)` — is not literally repeated in `resolved.rs`'s `QUILL` fixture, but the code path is type-agnostic, so this is a coverage nuance, not a real gap)
- **Coverage risk**: none for the deleted portions (same ladder, same producer function, proven equal to `compile_data` byte-for-byte). The nested-null test is the sole coverage for recursive null-zero-fill inside arrays/objects — must not be removed.

### F3: Two flagship-quill "vendored date region" regression tests duplicate one synthetic unit test's invariant
- **Category**: test-consolidation
- **Location**: `crates/quillmark/tests/usaf_memo_regions_test.rs:129-160` (`usaf_memo_date_region_rides_the_vendored_display`), `crates/quillmark/tests/cmu_letter_date_region_test.rs:15-49` (`cmu_letter_real_date_surfaces_a_region_and_blank_falls_back`)
- **Evidence**: Both are full end-to-end Typst compiles of a flagship quill (real fonts, real vendored `.typ` packages) asserting the identical #990 invariant: a `date`-typed field's `display` closure, called from inside a third-party package, still surfaces a clickable `regions()` entry keyed by schema path. `crates/backends/typst/tests/content_regions.rs:488-545` (`date_field_display_surfaces_a_clickable_region`) already pins this exact mechanism with a minimal synthetic quill (`(data.issued.display)(...)`, no fonts dir, no vendored package) — same assertions (region exists, positive area, `field_at` resolves back to the field). Running the same architectural check twice more, each via a full flagship compile, buys confidence that *these two specific vendored packages* don't break the mechanism, but that is a narrower claim than the test names suggest and the two flagship tests do not check anything of each other's packages.
- **Recommendation**: Keep one flagship regression (suggest `usaf_memo`'s, since `usaf_memo_regions_test.rs` already carries the broader body/signature/card region coverage in the same file/session) and drop `cmu_letter_date_region_test.rs` entirely, or fold its assertion into the same file as a second case sharing setup.
- **Est. LOC removable**: ~49 LOC and one full flagship Typst compile (opens a session + one `apply`) removed from CI per run
- **Confidence**: medium
- **Coverage risk**: dropping `cmu_letter_date_region_test.rs` loses the only proof that `cmu_letter`'s specific vendored `utils.typ` `display-date` doesn't regress span tracking — a real, if narrow, risk if that package is ever touched. If `cmu_letter` sees active maintenance, keep both; if it is a stable/vendored-once fixture, the synthetic unit test plus one flagship regression is sufficient.

### F4: `convert_fuzz.rs`'s mark-mapping "fuzz" tests are deterministic and duplicate the backend's own emit tests
- **Category**: subsumes-unit-tests
- **Location**: `crates/fuzz/src/convert_fuzz.rs:250-333` (`single_marks_map_to_typst_functions`, `nested_two_marks_map_both_functions`, `adjacent_and_triple_nested_marks_map`, `intraword_marks_map`, `test_underline_with_bold_inside`, `test_all_four_adjacent_no_space`, `test_interleaved_formats_with_text`, `test_format_at_word_boundaries`)
- **Evidence**: The file's own comment at `convert_fuzz.rs:240-248` states these were "Collapsed to example tests... deterministic unit tests in a proptest costume," having been downgraded from real proptests but never relocated. They call `mark_to_typst` (`import::from_markdown` + `quillmark_typst::emit::emit_content`) to check bold/italic/underline/strike mapping to `#strong[`/`#emph[`/`#underline[`/`#strike[`. `crates/backends/typst/src/emit.rs`'s own `#[cfg(test)] mod tests` (e.g. around line 1275, `assert_eq!(emit(m).markup, "#strong[#emph[x]]\n\n")`, plus the table/inline/nested-mark tests through the file) exercises the identical `emit_content` function with equal or stricter (exact-string, not `.contains()`) assertions, in the crate that owns the code.
- **Recommendation**: Delete these 8 functions from `crates/fuzz`; if any specific case (e.g. `test_underline_with_bold_inside`) is not already an exact case in `emit.rs`, port just that assertion there instead of keeping a duplicate copy in the fuzz crate.
- **Est. LOC removable**: ~85
- **Confidence**: medium — the invariant (mark→function mapping) is real and covered, but a line-by-line diff of every case against `emit.rs` was not exhaustively performed; spot checks (nested, adjacent, intraword) all found an equivalent or stronger existing test.
- **Coverage risk**: none identified; `emit.rs` tests the same production function.

### F5: `convert_fuzz.rs`'s hand-picked "attack vector" tests are subsumed by its own property tests plus the backend's escape tripwire
- **Category**: subsumes-unit-tests
- **Location**: `crates/fuzz/src/convert_fuzz.rs:23-48` (`test_escape_string_security_attack_vectors`), `:50-59` (`test_escape_string_control_characters`), `:61-82` (`test_escape_markup_security_attack_vectors`)
- **Evidence**: These hardcode specific "attack" strings and assert exact escaped output for `escape_string`/`escape_markup`. In the same file, `fuzz_escape_string_no_raw_quotes`, `fuzz_escape_markup_typst_chars_escaped`, and `fuzz_escape_markup_backslash_first` (`convert_fuzz.rs:84-141`) already prove the same "no unescaped quote/special-char/backslash count" invariants over arbitrary printable-Unicode input (`"\\PC*"`), which subsumes any fixed sample. Independently, `crates/backends/typst/src/emit.rs:1316-1358` (`escape_tripwire_markup`, `escape_tripwire_string_lit`) cross-checks every char of a curated sample set (control chars, backslashes, `//`, tildes, CJK, emoji) against a from-scratch reconstruction of the escaping rule, byte-for-byte — a stricter check than these three tests perform.
- **Recommendation**: Delete the three hardcoded tests; the "security" framing (SQL/eval-injection-style strings) is narrative color, not a distinct code path.
- **Est. LOC removable**: ~35
- **Confidence**: medium
- **Coverage risk**: none — same functions, already fuzzed generically and tripwired precisely elsewhere.

### F6: `parse_fuzz.rs`'s bare no-panic target is a strict subset of `emit_roundtrip_fuzz.rs`
- **Category**: weak-fuzz-target
- **Location**: `crates/fuzz/src/parse_fuzz.rs:4-8` (`fuzz_decompose_no_panic`)
- **Evidence**: Generates `s in "\\PC{0,1000}"` and only asserts `Document::parse` doesn't panic. `crates/fuzz/src/emit_roundtrip_fuzz.rs:33-64` (`fuzz_emit_roundtrip_arbitrary`) runs `Document::parse` over the same character class (`"\\PC{0,500}"`, difference is only the length bound) and, beyond not panicking on parse, additionally requires the emit→re-parse round trip to hold — a strictly stronger property over materially the same input space. A panic in `parse` would fail `fuzz_emit_roundtrip_arbitrary` too.
- **Recommendation**: Delete `fuzz_decompose_no_panic`; if the longer input bound (1000 vs 500 chars) is considered valuable, raise `fuzz_emit_roundtrip_arbitrary`'s bound instead of keeping a separate weaker target.
- **Est. LOC removable**: ~5
- **Confidence**: low-medium — proptest's per-target random shrinking means a second independent generator occasionally finds different edge cases faster in practice, so this is a minor, not clear-cut, redundancy.
- **Coverage risk**: negligible; the stronger roundtrip target's failure mode already includes "parse panicked."

### F7: `parse_fuzz.rs`'s remaining targets are weak — "doesn't panic" with almost no oracle
- **Category**: weak-fuzz-target
- **Location**: `crates/fuzz/src/parse_fuzz.rs:10-26` (`fuzz_decompose_with_fences`), `:28-43` (`fuzz_decompose_card_kinds`), `:64-86` (`fuzz_decompose_multiple_cards`)
- **Evidence**: Each generates a shaped input (card-yaml fences, a random card-kind name, N repeated card blocks) and, on successful parse, only touches accessors (`doc.cards()`, `doc.main().payload()`) without asserting anything about their values — a "doesn't panic" pattern the task brief calls out directly. `fuzz_decompose_large_payload` (`:45-60`) is the one target in this file with a real, if thin, oracle (`payload().len() <= size`). `emit_roundtrip_fuzz.rs`'s shaped generators (`fuzz_emit_roundtrip_payload_shaped`, `fuzz_emit_roundtrip_with_cards`) build comparably-shaped card-yaml documents and go further (roundtrip equality), covering the same "parse a card-kind-bearing document without panicking" ground.
- **Recommendation**: Delete `fuzz_decompose_with_fences`, `fuzz_decompose_card_kinds`, and `fuzz_decompose_multiple_cards`; keep `fuzz_decompose_large_payload` (it has a real assertion) and consider whether its shape is worth porting into `emit_roundtrip_fuzz.rs` as a fourth case instead of a separate file.
- **Est. LOC removable**: ~45
- **Confidence**: low — these are genuinely fuzz targets (not disguised unit tests like F4/F5), so there is some independent value in a second harness reaching the same code by a different route; flagging primarily because the oracle is essentially absent.
- **Coverage risk**: low; `emit_roundtrip_fuzz.rs` reaches the same parser code with a strictly stronger property over similarly shaped input.

### F8: `backend_registration_test.rs` and `quill_engine_test.rs` duplicate scaffolding for the same engine surface
- **Category**: test-consolidation
- **Location**: `crates/quillmark/tests/backend_registration_test.rs:59-107`, `crates/quillmark/tests/quill_engine_test.rs:8-87`
- **Evidence**: Both files independently define a ~15-20 line "write a minimal `Quill.yaml` + plate to a tempdir" helper (`create_test_quill`-shaped) and both test the `Quillmark` backend registry/dispatch surface — one via a custom `MockBackend`, the other via `register_backend`-adjacent checks (`test_unsupported_backend_errors_at_render_time` is effectively the negative case of `backend_registration_test.rs`'s custom-backend-succeeds case). No assertion is a literal duplicate, but the two files are testing one surface (`Quillmark::{register_backend, resolve_backend, render}`) with parallel, non-shared harnesses.
- **Recommendation**: Merge the two files (e.g. into `backend_registration_test.rs`), sharing one quill-scaffolding helper. Not a coverage change — pure duplication-of-harness cleanup.
- **Est. LOC removable**: ~15-20 (helper dedup only; keep all current assertions)
- **Confidence**: low
- **Coverage risk**: none — this is a pure merge, no test deleted.

## Keep (looks redundant, is the only coverage)

- `crates/quillmark/tests/quiver_test.rs` — the canonical parameterized "every fixture Quill loads, empty-document-renders, and blueprint-round-trips" test the other per-fixture tests are sometimes mistaken for duplicating. It only proves the *type-minimal* input renders; it carries none of the populated-content assertions (`$body` regions, signature widget position, real date regions, GFM tables) the other quillmark tests add, so those remain necessary on top of it, not instead of it.
- `crates/quillmark/tests/usaf_memo_regions_test.rs::usaf_memo_regions_cover_body_signature_and_cards` — the only end-to-end proof that the real `usaf_memo` package's AFH 33-337 auto-numbering rebuild (`render-body`'s show-rule state buffer) survives span tracking; the closest unit analog (`content_regions.rs::content_survives_a_rebuilding_show_rule`) uses a synthetic capture-and-replay plate, not the shipped package.
- `crates/quillmark/tests/usaf_memo_signature_test.rs` — the only test asserting the real memo package places its unsigned signature widget at the AFH-mandated 4.5in block rather than the 1in margin; `backends/typst/tests/sig_field.rs` tests the generic `signature-field`/`form-field` mechanism with synthetic plates, never the real package's specific placement math.
- `crates/quillmark/tests/version_mismatch_test.rs` — `check_quill_reference` (`crates/core/src/quill/compose.rs:151-180`) has no unit tests of its own anywhere in `quillmark-core`; this file is the sole coverage for `$quill` name/version mismatch handling.
- `crates/quillmark/tests/plaintext_render_test.rs` — the only test that drives a `plaintext`-typed field through a real Typst compile; core's schema/coercion tests cover the type declaration, not the backend lowering.
- `crates/quillmark/tests/table_render_test.rs` — the only end-to-end proof that the Typst emitter's `#table(...)` lowering (column alignment, ragged-row normalization) compiles and visibly draws; the inline codec's own unit tests only pin `import(export(t))`, not the rendered path.
- Fixture inventory: all 7 quills under `resources/quills/` (`classic_resume`, `cmu_letter`, `richtext_form`, `sample_form`, `table_demo`, `taro`, `usaf_memo`) and all 4 loose resource files (`sample.md`, `card_yaml_demo.md`, `extended_metadata_demo.md`, `ambiguous_strings.md`) are loaded by at least one test somewhere in the workspace (verified by grep across `crates/*/tests`, `crates/*/src`, `crates/core/examples`) — `classic_resume` is unused within `crates/quillmark` specifically but is exercised by `crates/core/src/quill/tests.rs` and `crates/core/examples/print_blueprint.rs`, so it is not dead weight overall. No unused-fixture finding.
- `crates/fuzz/src/coerce_fuzz.rs` — a well-built fuzz target throughout: T1-T3 (no-panic, well-formed error path, idempotence) plus the mirrored W1-W3 write-side properties, each with a real, checkable oracle. No findings against it.
- `crates/fuzz/src/emit_roundtrip_fuzz.rs` — the strongest target in the crate (parse→emit→re-parse identity plus emit idempotence); both `proptest-regressions/*.txt` files show it and `convert_fuzz.rs`'s property tests have actually caught real regressions in the past, evidencing genuine value.
